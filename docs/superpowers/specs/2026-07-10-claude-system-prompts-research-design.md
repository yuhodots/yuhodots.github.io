# Claude System Prompts Research Design

## Goal

공개 GitHub 저장소에 게시된 네 개의 비공식 Claude 시스템 프롬프트 자료를 직접 분석하여, 모델별로 독립적인 한국어 기술 분석 문서를 `docs/research/`에 작성합니다. 각 문서는 frontmatter 없이 읽을 수 있는 연구 노트이며, 원문의 전체 구조, 핵심 항목, 특징, 요약을 상세히 설명합니다.

## Scope

분석 대상과 출력 파일은 다음과 같습니다.

| 대상 | 주 출처 | 출력 파일 |
| --- | --- | --- |
| Claude Code Opus 4.8 | `claude-code-opus-4.8.md` | `docs/research/260710-claude-code-opus4-8-system-prompt-summary copy 2.md` |
| Claude Sonnet 5 | `claude-sonnet-5.md` | `docs/research/260710-claude-sonnet5-system-prompt-summary copy 3.md` |
| Claude Opus 4.8 | `claude-opus-4.8.md` | `docs/research/260710-claude-opus4-8-system-prompt-summary.md` |
| Claude Fable 5 | `claude-fable-5.md` | `docs/research/260710-claude-fable5-system-prompt-summary.md` |

기존에 만들어진 네 개의 빈 파일을 그대로 사용하며, 파일 이름을 변경하거나 게시용 포스트를 별도로 만들지 않습니다.

## Source Policy

- 사용자가 제공한 GitHub 원문을 각 문서의 1차 자료로 사용합니다.
- 원문의 실제 내용과 계층을 직접 확인하고, 구조나 규칙을 추측하지 않습니다.
- 자료는 Anthropic이 공식 배포한 문서가 아닌 비공식 수집본이라는 점을 문서 앞부분에 명시합니다.
- 원문이 특정 시점의 스냅샷일 수 있고 실제 서비스 프롬프트 전체와 일치한다고 보장할 수 없다는 한계를 밝힙니다.
- 원문을 대량으로 옮기지 않고 한국어 해설과 요약을 중심으로 작성합니다. 필요한 경우에만 짧은 문구를 인용합니다.
- 세부 기능을 보충 설명해야 할 때만 Anthropic의 공식 문서를 추가 출처로 사용하고, 원문에서 확인되는 내용과 보충 설명을 구분합니다.

## Writing Approach

원문 순서를 그대로 번역하는 방식과 주제별로 완전히 재배열하는 방식의 중간 형태를 사용합니다. 먼저 원문의 최상위 계층과 지시 흐름을 복원한 다음, 핵심 규칙을 역할별로 묶어 설명합니다. 이를 통해 원문 구조를 추적할 수 있으면서도 번역본이 아닌 독립적인 분석 문서가 되도록 합니다.

본문은 최근 블로그 글의 문체를 참고하여 한국어 `~합니다/~입니다.` 체로 작성합니다. 단락은 한 가지 주제에 집중하고, 복잡한 계층은 표나 Mermaid 다이어그램을 사용해 설명합니다. 문서 목적상 frontmatter와 게시용 AI 고지 문구는 넣지 않습니다.

## Shared Document Structure

네 문서는 다음 공통 구조를 사용합니다.

1. 제목과 문서 범위
2. 출처 성격 및 해석상의 주의사항
3. 전체 개요
4. **전체적인 구조**
   - 최상위 지시 계층
   - 컨텍스트 및 메타데이터 구성
   - 응답 또는 도구 실행 흐름
   - 주요 섹션 간 관계
5. **핵심 항목**
   - 모델 정체성과 역할
   - 사용자 요청 해석과 우선순위
   - 추론·응답·문체 규칙
   - 도구 사용과 권한 경계
   - 안전 및 거절 규칙
   - 시간·지식·인용 관련 규칙
   - 모델별로만 존재하는 주요 지침
6. **특징**
   - 반복적으로 강조되는 설계 원칙
   - 일반 대화 모델 또는 코딩 에이전트로서의 차별점
   - 프롬프트 설계가 실제 행동에 미치는 영향
   - 강점, 긴장 관계, 해석 시 주의점
7. **요약**
   - 핵심 포인트
   - 실무적 시사점
8. References

원문에 존재하지 않는 항목을 억지로 채우지 않습니다. 예를 들어 일반 대화 모델에 코딩 도구 계약이 없다면, 해당 부재 자체를 Claude Code 버전과의 차이로 설명합니다.

## Model-Specific Focus

### Claude Code Opus 4.8

도구 기반 코딩 에이전트의 실행 계약을 중심으로 분석합니다. 시스템·개발자·사용자 지시의 우선순위, 저장소 지침 탐색, 계획과 진행 보고, 파일 편집, 셸 실행, 권한 상승, Git 안전성, 검증과 완료 보고, 서브 에이전트 활용 규칙을 구조화합니다.

### Claude Sonnet 5

일반 대화 모델로서의 정체성, 지식 및 시간 처리, 사용자 의도 해석, 답변 형식, 안전 정책, 인용과 저작권 제약이 어떻게 결합되는지 분석합니다. 다른 일반 Claude 모델과 비교 가능한 반복 규칙과 Sonnet 5에 특화된 강조점을 구분합니다.

### Claude Opus 4.8

복잡한 요청을 다루는 응답 태도와 추론 규율, 안전 경계, 정직성과 불확실성 표현, 도구나 외부 정보에 관한 규칙을 중심으로 분석합니다. Claude Code Opus 4.8과 이름은 유사하지만 역할과 실행 환경이 다른 점을 분명히 합니다.

### Claude Fable 5

창작 및 서술 성향과 관련된 지시가 있는지, 일반 안전·정직성 규칙과 어떤 관계를 이루는지 분석합니다. 이름에서 예상되는 성격을 추정하지 않고 원문에 실제로 존재하는 규칙만 근거로 특징을 도출합니다.

## Parallel Work Plan

세 개의 서브 에이전트가 Claude Sonnet 5, Claude Opus 4.8, Claude Fable 5를 각각 담당합니다. 메인 에이전트는 도구 및 저장소 작업 규칙이 가장 많은 Claude Code Opus 4.8을 담당합니다. 각 작업자는 자신에게 배정된 원문과 출력 파일만 수정하여 파일 충돌을 방지합니다.

모든 작업자는 공통 목차, 출처 고지, 한국어 문체, 원문 중심 분석이라는 동일한 계약을 따릅니다. 병렬 작업이 끝나면 메인 에이전트가 네 파일을 함께 검토하여 목차 깊이, 용어, 인용 형식, 중복 수준을 통일합니다.

## Quality Checks

- 네 출력 파일이 모두 비어 있지 않고 각 모델에 맞는 내용을 담고 있어야 합니다.
- 각 문서에 전체적인 구조, 핵심 항목, 특징, 요약이 명시적으로 존재해야 합니다.
- 모델명, 버전, 도구명, 지시 계층에 관한 설명을 원문과 대조합니다.
- 원문에 없는 정책이나 기능을 사실처럼 추가하지 않습니다.
- 네 문서가 같은 문장을 기계적으로 반복하지 않도록 모델별 차이를 충분히 설명합니다.
- 짧은 직접 인용을 제외하고는 한국어로 재서술합니다.
- 모든 문서 끝에 사용자가 제공한 해당 GitHub 원문 링크를 포함합니다.
- Markdown 헤더 계층, 표, 코드 블록, Mermaid 구문이 정상적으로 닫혀 있는지 확인합니다.
- `TODO`, `TBD`, 미완성 문장, 빈 섹션이 남지 않도록 검사합니다.

## Out of Scope

- 시스템 프롬프트의 진위 여부를 독립적으로 입증하는 작업
- 네 모델의 실제 성능 벤치마크 또는 응답 실험
- 시스템 프롬프트 원문 전체의 한국어 번역
- `contents/` 아래의 게시용 블로그 포스트 작성
- Gatsby 빌드, 개발 서버 실행, 배포
